## 二、leek-trader 当前状态总结

### 2.1 已完成的核心能力

✅ 行情服务（新浪/东方财富/腾讯/BaoStock 多源降级 + 双层缓存）  
✅ 策略引擎（双均线 / MACD / RL 实验策略 + 插件化注册）  
✅ 交易执行（T+1 / 涨跌停 / 停牌 + 8 项风控规则）  
✅ 持仓账户（Order/Trade/Position/CashFlow 四表联动）  
✅ 盈亏报表（胜率/盈利因子/最大回撤/累计收益）  
✅ 智能选股（日报生成 + 评分 + 机构池 + Celery 调度）  
✅ AI 分析（单票 AI + 流式投资助手 + 多模型配置）  
✅ RL 训练台（PPO + 模拟环境 + 模型状态管理）  
✅ 用户认证（JWT + 数据隔离）  
✅ 市场资讯（快讯 + 九研讨论）  

### 2.2 核心缺失（对比开源项目）

❌ **策略回测引擎** — 最核心缺口，历史数据已有但未接入回测框架  
❌ **自绘 K 线图** — 当前靠 iframe 内嵌东方财富，体验差且依赖外部  
❌ **股票池多维度筛选** — 设计文档 Phase 1 Step 2，几乎未开始  
❌ **夏普比率/年化收益率** — 报表缺乏关键量化绩效指标  
❌ **基准收益对比** — 资产曲线无沪深 300 基准线  
❌ **风控参数可视化** — 风控阈值硬编码，用户无法配置  
❌ **收盘自动复盘** — 设计文档 Phase 2 Step 9，未开始  
❌ **更多内置策略** — RSI / 布林带 / KDJ / 均值回归等均缺失

## 三、功能优化计划

### 3.1 优先级排序原则

- **P0（立即做）**：影响核心使用体验，对标开源项目普遍具备的基础能力
- **P1（近期做）**：增强系统竞争力，与开源项目差异化能力对齐
- **P2（中期做）**：锦上添花，提升用户体验和专业度

---

### 3.2 P0 优先级优化项

#### P0-1：策略回测引擎

**参考项目**：vnpy、QUANTAXIS、OSKHQuant、jin-ce-zhi-suan  
**当前状态**：BaoStock 历史日线数据已同步存储，但无回测框架接入  
**缺口描述**：用户无法验证策略在历史行情中的有效性，是量化系统最核心的缺失功能

**优化方案**：
1. **后端：回测引擎服务** (`backend/app/backtest/`)
   - `BacktestEngine`：驱动历史数据逐日回放，触发策略信号计算
   - `BacktestAccount`：独立回测账户，管理虚拟持仓/现金/交易记录
   - `BacktestMetrics`：计算年化收益率、夏普比率、最大回撤、胜率、盈利因子、Calmar 比率
   - 复用现有 `strategy/strategies/` 下的策略插件，不重复开发策略逻辑
   - 支持自定义回测区间（起止日期）和初始资金

2. **后端：回测 API** (`/api/v1/backtest`)
   - `POST /backtest/run`：提交回测任务（策略ID + 区间 + 初始资金）
   - `GET /backtest/{id}`：查询回测任务状态和结果
   - 通过 Celery 异步执行回测，前端轮询结果

3. **前端：回测结果页**（在 `StrategiesView.vue` 内新增回测 Tab 或 Drawer）
   - 配置区：选择回测区间、初始资金、策略参数
   - 结果区：回测权益曲线（ECharts 折线图）+ 关键指标卡片
   - 与实盘权益曲线对比展示

**验收标准**：至少双均线策略可完成完整回测，结果含年化收益率、夏普比率、最大回撤

---

#### P0-2：自绘 K 线图（替换 iframe 方案）

**参考项目**：vnpy（K线图组件）、ECharts 金融图表  
**当前状态**：`StockDetailView.vue` 通过 iframe 内嵌东方财富，无法控制样式/交互/数据  
**缺口描述**：iframe 方案在移动端显示差、加载慢、无法整合自定义指标

**优化方案**：
1. **后端：K 线数据 API**（BaoStock/东方财富历史日线已有，补充接口）
   - `GET /api/v1/market/kline?symbol=sh600519&period=day&count=250`
   - 返回标准 OHLCV + 成交量数据

2. **前端：ECharts K 线组件**（`frontend/src/components/KLineChart.vue`）
   - 使用 ECharts `candlestick` 图表类型
   - 支持日线/周线/月线切换
   - 叠加 MA5/MA10/MA20/MA60 均线
   - 副图：MACD（柱状 + 双线）、成交量、KDJ（可选）
   - 支持缩放、十字光标

3. **前端：升级个股详情页**（`StockDetailView.vue`）
   - 用自绘 K 线图替换 iframe
   - 上方行情摘要（最新价/涨跌幅/成交量/换手率）
   - 右侧快速 AI 分析入口

**验收标准**：个股详情页展示自绘 K 线图，支持 MA 均线叠加和时间范围缩放

---

#### P0-3：股票池多维度筛选

**参考项目**：AData、stock-analysis、设计文档 Phase 1 Step 2  
**当前状态**：几乎未开始，设计文档已定义需求  
**缺口描述**：用户无法按条件构建股票池，是智能选股和策略配置的基础依赖

**优化方案**：
1. **后端：基础股票信息表**
   - 新增 `StockInfo` 模型：code/name/market/industry_sw/market_cap_level/is_st/is_listed
   - 通过 BaoStock 或东方财富接口每日同步全市场约 5000 只股票基础信息
   - 新增 Celery 定时任务：每日收盘后同步一次

2. **后端：筛选 API**（`/api/v1/screener`）
   - 支持过滤参数：market（沪/深/创业板/科创板/北交所）、industry_sw（申万一级）、market_cap（大/中/小盘）、not_st（排除ST）、recent_change_pct（近5日涨跌幅范围）
   - 返回分页股票列表 + 基础行情
   - 支持保存筛选条件为命名股票池

3. **前端：股票筛选器页面**（新增 `ScreenerView.vue`）
   - 左侧：筛选条件面板（市场/行业/市值/ST过滤/技术条件）
   - 右侧：筛选结果表（支持一键加入自选股或策略标的池）
   - 保存/加载自定义筛选方案

**验收标准**：可按市场+行业+市值三个维度筛选股票，结果可加入自选股

---

#### P0-4：关键绩效指标补全（夏普比率/年化收益率）

**参考项目**：几乎所有量化项目均包含这两项指标  
**当前状态**：`reporting/service.py` 缺少夏普比率和年化收益率计算  

**优化方案**：
1. **后端**：在 `ReportingService.get_summary()` 中补充计算：
   - **年化收益率**：`(期末权益 / 初始资金)^(365/持仓天数) - 1`
   - **夏普比率**：`(年化收益率 - 无风险利率(2.5%)) / 年化收益率标准差`
   - **Calmar 比率**：`年化收益率 / |最大回撤|`
   - 基于 `EquitySnapshot` 每日快照计算

2. **前端**：在 `AnalysisView.vue` 的指标卡片中新增夏普比率和年化收益率展示

**验收标准**：盈亏复盘页新增夏普比率、年化收益率、Calmar 比率三项指标

### 3.3 P1 优先级优化项

#### P1-1：资产曲线基准对比（沪深 300 基准线）

**参考项目**：vnpy、OSKHQuant 均有基准对比  
**优化方案**：
- 获取沪深 300 指数（sh000300）同期历史涨跌幅，叠加到资产曲线 ECharts 图表中
- 显示为虚线"基准"系列，颜色区分于实盘权益曲线

---

#### P1-2：风控参数可视化配置

**当前状态**：`RiskService` 中单股持仓比 0.2、总仓位比 0.9、日亏损熔断 0.05、日交易次数 20 全部硬编码  
**优化方案**：
- 将风控参数迁移到 `AppPreference` 的 `trading_preferences` JSON 字段
- 在 `SettingsView.vue` 新增"风控边界"配置区（滑块或数字输入）
- `RiskService.validate_order()` 改为从 `PreferenceService` 读取动态参数

---

#### P1-3：更多内置策略（RSI / 布林带 / KDJ）

**参考项目**：MyTT（通达信指标移植）、rockyzsu/stock  
**优化方案**：
- 新增 `strategy/strategies/rsi.py`：RSI 超买/超卖策略
- 新增 `strategy/strategies/bollinger.py`：布林带突破策略
- 新增 `strategy/strategies/kdj.py`：KDJ 金叉/死叉策略
- 前端 `StrategiesView.vue` 创建策略时，策略类型下拉新增上述选项

---

#### P1-4：收盘自动复盘（AI 日报）

**参考项目**：设计文档 Phase 2 Step 9，leek-fund 参考实现  
**优化方案**：
- 新增 Celery Beat 定时任务：每日 15:05 触发 `run_daily_review_task`
- 聚合当日市场数据（指数涨跌 + 板块资金 + 北向资金）
- 聚合个人数据（当日交易 + 持仓表现 + 策略运行结果）
- 调用 AI 接口生成结构化复盘报告（Markdown 格式）
- 存储到新增 `DailyReview` 模型，前端新增"每日复盘"页面

---

#### P1-5：WebSocket 实时行情推送

**当前状态**：前端依赖轮询（每 30 秒），实时性差  
**优化方案**：
- 后端添加 FastAPI WebSocket 端点：`/ws/quotes`
- 推送订阅标的的实时报价（10 秒间隔）
- 前端 `WatchlistView.vue` 连接 WebSocket，实时更新价格和涨跌幅
- 降低无效 HTTP 请求，提升盯盘体验

---

#### P1-6：交易记录导出（CSV/Excel）

**参考项目**：vnpy、大多数量化系统均支持导出  
**优化方案**：
- 后端 `/api/v1/trades/export` 接口，支持 CSV 格式下载
- 包含字段：日期/股票代码/股票名/方向/成交价/数量/手续费/盈亏
- 前端 `PortfolioView.vue` 添加"导出历史成交"按钮

---

### 3.4 P2 优先级优化项

#### P2-1：持仓分布图（行业/市值饼图）

- 在 `AnalysisView.vue` 新增持仓分布 ECharts 饼图
- 展示当前持仓按行业和仓位占比的分布情况

#### P2-2：策略绩效对比

- 在 `AnalysisView.vue` 新增策略绩效对比区
- 展示各策略的累计收益、胜率、最大回撤的横向对比柱状图

#### P2-3：多账户模拟

- 支持用户创建多个模拟账户（不同初始资金/风控参数）
- 用于对比不同策略在独立账户中的表现

#### P2-4：多 AI 智能体协作分析

**参考项目**：OficcEJO/AIAgents-Stock（1.3k Stars）  
- 模拟"分析师团队"：技术分析师 + 基本面分析师 + 情绪分析师三个 Agent 协作生成分析报告
- 可在现有 AI 分析页面新增"团队分析"模式

#### P2-5：自定义策略脚本上传

**参考项目**：设计文档已规划、vnpy 已实现  
- 支持用户上传 Python 策略脚本（沙箱执行）
- 策略需继承 `BaseStrategy` 并实现 `generate_signal()` 方法

## 六、结论

当前 leek-trader 已完成了一个功能覆盖面相当广的模拟交易 MVP，核心交易闭环（行情→策略→风控→下单→持仓→报表）已完整打通，并额外实现了 AI 分析和 RL 训练台等亮点功能。

**与主流开源量化项目相比，最核心的三个差距是**：

1. **策略回测引擎缺失**：这是所有量化系统的标配能力，18/20 个参考项目均已实现，当前项目缺失导致用户无法验证策略有效性
2. **K 线图依赖第三方 iframe**：无法定制化，体验差，16/20 个项目均有自绘 K 线
3. **股票池筛选功能未实现**：设计文档已规划但几乎未开始，是"能用"到"好用"的关键跨越

**建议的下一步行动顺序**：
1. 先做"快赢"——用半天完成绩效指标补全和风控参数配置（立竿见影，代码量小）
2. 然后做"主战场"——策略回测引擎和自绘 K 线图（2–3 周）
3. 再补"基础能力"——股票池筛选（1 周）
4. 最后完成"增强功能"——收盘复盘、WebSocket、更多策略等
