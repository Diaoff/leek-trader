# 演进边界说明

Leek Trader 当前定位是本地单用户 A 股研究与模拟交易系统。本文件只记录未来扩展边界，不把系统提前改造成 SaaS、多租户或真实交易平台。

## 租户上下文

- 当前唯一运行租户由 `DEFAULT_TENANT_ID` 配置，默认值为 `local`。
- `tenant_id` 字段用于隔离本地样本数据、保留未来迁移路径，以及避免新增模型时丢失作用域。
- 服务层可以通过 `TenantContext` 传递当前本地租户与用户信息，但不得接受外部请求任意切换租户。
- 当前不实现租户注册、租户路由、租户级账单、租户级数据迁移或跨租户管理后台。

## 数据访问边界

- 新增本地业务数据模型时，应包含必要的 `tenant_id` 和 `user_id` 作用域字段。
- 查询用户私有数据时，应同时约束 `tenant_id` 与 `user_id`，公共市场数据除外。
- 当前不引入通用 Repository、租户分库分表、行级安全策略或跨租户查询层；这些能力需要单独设计和迁移方案。

## 权限与角色边界

- 当前只保留本地账号的 `is_active` 和 `is_superuser` 边界，用于区分普通用户与本地管理操作。
- 不实现生产级 RBAC、权限矩阵、组织成员管理、审计审批流或细粒度资源授权。
- 新增高风险操作应优先复用现有 superuser 依赖，而不是新增局部权限模型。

## 配额与资源边界

- 当前不实现计费、套餐、租户配额或商业化限流。
- 面向稳定性的限制可以在任务、导出、回测或训练入口做本地参数校验，但应解释为本地资源保护，不应包装为 SaaS 配额。
- 如果未来需要配额，应先定义资源维度、计量口径、失败语义和迁移策略。

## 部署演进路线

1. 本地开发：`./start.sh` 启动后端与前端，按需启用异步任务。
2. 单机私有化：使用 Docker Compose 或 all-in-one 脚本部署 Postgres、Redis、后端和前端。
3. 小团队私有化：只在完成权限、审计、备份、监控和数据隔离设计后再考虑。
4. SaaS 化：当前不做；必须先补租户管理、权限、配额、合规、运维和数据隔离方案。

## API 与服务兼容性

- 当前 API 优先服务本地 UI 和测试，不承诺外部公共 API 稳定性。
- 已暴露给前端的字段应保持向后兼容；需要删除或改名时，应同步更新前端类型、README 或计划文档。
- 新增接口应保留清晰的输入输出 Schema，避免返回内部 ORM 对象。
- 异步任务、回测、复盘和训练结果应保留可查询状态，避免只依赖进程内瞬态状态。

## 数据源使用边界

- 行情、新闻和历史数据来自第三方公开数据源，可能受到网络、限流、交易日历、字段变更和服务稳定性影响。
- 本项目仅用于研究和模拟交易，不构成投资建议，不保证数据实时性、完整性或适用于实盘。
- 不直接复制许可证不兼容项目代码；只能借鉴公开架构思想，并保留来源边界说明。
