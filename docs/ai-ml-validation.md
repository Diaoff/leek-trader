# AI/ML 验证与边界

## 目标

第六批只启动 AI/ML 深化的最小可验证设计：样本外验证、Walk-Forward、漂移监控、自然语言策略分析和参数推荐都保持只读、可解释、可回滚，不自动实盘，不自动修改策略参数。

## Walk-Forward 最小方案

最小接口边界以现有 RL 训练任务和模型注册表为基础，不强行扩展存储模型：

1. 输入训练窗口、验证窗口、滚动步长、symbol 列表、策略或模型版本。
2. 每个窗口只使用训练窗口内数据拟合或选择参数。
3. 在紧随其后的验证窗口运行只读评估，记录收益、回撤、交易次数和超额收益。
4. 汇总所有窗口的平均值、最差值、通过/失败原因。
5. 结果先以服务层摘要和文档验收为主，等结构稳定后再持久化完整窗口明细。

最小验收标准：同一输入可复现同一窗口切分；验证窗口不得泄漏未来数据；窗口摘要包含足够字段定位退化原因。

## 漂移与性能退化指标

模型漂移监控先采用可解释的绩效口径，而不是黑盒统计告警：

| 指标 | 说明 |
| --- | --- |
| `validation_return_pct` | 最近样本外验证收益率 |
| `validation_max_drawdown_pct` | 最近样本外验证最大回撤 |
| `validation_trade_count` | 最近验证窗口交易次数 |
| `validation_excess_return_pct` | 相对买入持有或基准的超额收益 |
| `last_trained_at` | 最近训练完成时间 |
| `last_validated_at` | 最近样本外验证完成时间 |

退化判定先使用保守规则：验证收益显著低于训练期、最大回撤超过策略预设阈值、交易次数异常降为 0、超额收益连续为负，均应标记为需要人工复核。

## 自然语言策略分析入口

自然语言入口只读取已有事实：策略表现、回测摘要、模型指标、训练参数和验证摘要。允许回答：

- 某策略近期表现为何变差。
- 某模型的样本外收益、回撤和交易次数是否稳定。
- 某次参数调整相比上一版本改善了哪些指标。
- 哪些策略需要重新训练或人工复核。

禁止行为：不生成不可解释交易代码；不自动提交订单；不自动修改策略参数；不把外部大模型输出当作事实来源覆盖本地指标。

## 参数推荐边界

参数推荐先做只读建议，不直接写入策略配置：

- 推荐必须引用历史回测或验证摘要中的指标证据。
- 推荐必须说明预期改善目标，例如降低回撤、提高交易频率稳定性或改善超额收益。
- 推荐必须保留原参数、建议参数和风险提示。
- 用户确认前不得自动更新策略或模型配置。

## 成本、稳定性和可解释性边界

- 成本：默认优先本地指标与轻量摘要；外部大模型只用于解释性文本，不用于高频循环。
- 稳定性：AI/ML 任务失败不得影响行情、交易、持仓和账户主链路。
- 可解释性：每个模型建议必须能追溯到训练参数、数据范围和验证指标。
- 安全：`active` 模型不等于自动实盘；交易仍受策略执行模式、风控校验和用户动作约束。
